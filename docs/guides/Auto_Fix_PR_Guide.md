# Auto-Fix PR Creation Guide

## Overview

The Agentic Pipeline now includes automatic PR creation with fixes when it identifies and can safely resolve pipeline failures. This feature uses Claude AI to analyze failures and generate code fixes, then automatically creates a pull request with the changes.

## How It Works

### Workflow

1. **GitHub Actions webhook** triggers when a workflow fails
2. **Pipeline orchestration** analyzes the failure using RCA and pattern detection
3. **Confidence check**: If the failure analysis has high confidence (>= threshold)
4. **Fix generation**: Claude analyzes the failure and generates a potential fix
5. **Safety validation**: The system checks if the fix is safe to apply automatically
6. **PR creation**: If safe, creates a new branch, commits the changes, and opens a PR

### Safety Rules

The auto-fix system follows strict safety rules:

- **Only fixes simple, well-understood issues:**
  - Syntax errors
  - Missing imports
  - Typos in code
  - Simple configuration mistakes

- **Never fixes complex issues:**
  - Logic errors requiring human judgment
  - Architectural changes
  - Database schema modifications
  - Security-sensitive code changes
  - Configuration files with broad impact

- **Confidence thresholds:**
  - Minimum confidence for auto-fix generation: 80% (failure analysis)
  - Minimum confidence for PR creation: 90% (by default)

## Configuration

### appsettings.json

```json
{
  "Notifications": {
    "CreateAutoFixPRs": false,
    "MinConfidenceForAutoFixPR": 0.9
  }
}
```

### appsettings.Development.json

```json
{
  "Notifications": {
    "CreateAutoFixPRs": true,
    "MinConfidenceForAutoFixPR": 0.85
  }
}
```

### Configuration Options

| Setting | Type | Default | Description |
|---------|------|---------|-------------|
| `CreateAutoFixPRs` | boolean | `false` | Enable/disable automatic PR creation with fixes |
| `MinConfidenceForAutoFixPR` | decimal | `0.9` | Minimum confidence threshold (0.0-1.0) required to create auto-fix PRs |

**Note:** Lower thresholds in development (0.85) allow more testing opportunities, while production should use higher thresholds (0.9+) for safety.

## Auto-Fix Process Details

### 1. Failure Analysis

The system must have:
- Completed failure analysis with RCA
- Confidence score >= 80%
- Identified error type and root cause
- Generated recommendations

### 2. Fix Generation

Claude analyzes:
- Error type and root cause
- Detailed analysis from RCA
- Recommendations from the failure analysis
- Current file contents (up to 5 affected files)

Claude generates:
- Fix description
- Confidence level (0.0-1.0)
- Safety assessment (`isSafeToApply`)
- List of file changes with reasons

### 3. File Changes

Each file change includes:
- **FilePath**: Relative path from repository root
- **ChangeType**: Modify, Create, or Delete
- **NewContent**: Complete new file content
- **ChangeReason**: Explanation of why this fixes the issue

### 4. PR Creation

If the fix is safe:
- Creates branch: `autofix/{error-type}-{timestamp}`
- Commits each file change with descriptive message
- Opens PR with detailed body containing:
  - Fix description and confidence
  - Original failure analysis
  - Changes made with explanations
  - Warning to review carefully

## Pull Request Format

### PR Title
```
[Auto-Fix] {ErrorType}: {RootCause}
```

Example:
```
[Auto-Fix] CompilationError: Missing namespace import for JsonSerializer
```

### PR Body

```markdown
## Automatic Fix Generated

**Confidence:** 95%
**Fix Description:** Add missing System.Text.Json using statement

## Original Failure Analysis

**Error Type:** CompilationError
**Root Cause:** JsonSerializer is not recognized in the current context

### Recommendations
- Add using System.Text.Json directive
- Verify JSON serialization implementation
- Check for NuGet package reference

## Changes Made
- **src/Services/DataService.cs** (Modify): Added missing System.Text.Json using directive

---
*This PR was automatically generated by Agentic Pipeline (Orchestration ID: `abc-123`)*

⚠️ **Please review carefully before merging!** This fix was generated automatically and may require adjustments.
```

## Testing the Feature

### 1. Enable in Configuration

Edit `appsettings.Development.json`:
```json
{
  "Notifications": {
    "CreateAutoFixPRs": true,
    "MinConfidenceForAutoFixPR": 0.85
  }
}
```

### 2. Trigger a Failure

Create a workflow that will fail with a simple, fixable issue:

```yaml
name: Test Auto-Fix
on:
  workflow_dispatch:

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Build with error
        run: dotnet build
```

Introduce a simple error in your code (e.g., remove a using statement).

### 3. Monitor Logs

Watch the API logs for:
```
Attempting to generate auto-fix for orchestration {id}
Auto-fix generated successfully. Creating PR...
Created auto-fix PR #{number} for orchestration {id}
```

### 4. Review the PR

Check GitHub for the new PR:
- Branch name: `autofix/*`
- Title: `[Auto-Fix] ...`
- Review the changes carefully
- Test the fix before merging

## Troubleshooting

### Fix Not Generated

**Symptom:** No PR created despite failure
**Possible causes:**
- Confidence too low (`< MinConfidenceForAutoFixPR`)
- Claude determined fix is not safe to apply
- Issue is too complex for automatic fixing
- GitHub token lacks required permissions

**Check logs for:**
```
Skipping auto-fix due to low confidence: {score} < {threshold}
Auto-fix not generated or not safe to apply: {reason}
```

### PR Creation Failed

**Symptom:** Fix generated but PR not created
**Possible causes:**
- GitHub authentication issues
- Branch already exists
- File conflicts
- Network errors

**Check logs for:**
```
Failed to create auto-fix PR for orchestration {id}
Error applying auto-fix and creating PR
```

### Wrong Files Modified

**Symptom:** PR modifies incorrect files
**Possible causes:**
- Claude misidentified affected components
- Insufficient context provided
- File paths incorrect

**Solution:** This is why PRs require human review. Close the PR and investigate the root cause manually.

## Best Practices

### 1. Start Conservatively
- Begin with high confidence thresholds (0.9+)
- Monitor generated PRs carefully
- Adjust thresholds based on results

### 2. Review All Auto-Fix PRs
- Never auto-merge auto-fix PRs
- Test the changes in a staging environment
- Verify the fix addresses the root cause

### 3. Provide Feedback
- Close PRs that miss the mark with explanatory comments
- This helps identify patterns where auto-fix needs improvement

### 4. Use GitHub Branch Protection
- Require reviews for all PRs
- Require passing CI checks
- Prevent direct merges from `autofix/*` branches

### 5. Monitor Performance
- Track success rate of auto-fix PRs
- Measure time saved vs. review overhead
- Adjust `MinConfidenceForAutoFixPR` based on data

## Architecture

### Components

- **IAutoFixService** (Core): Interface defining auto-fix operations
- **AutoFixService** (Infrastructure): Implementation using Claude and GitHub API
- **AutoFixResult** (Core): Model representing fix results
- **WebhookController** (API): Orchestrates auto-fix during webhook processing

### Dependencies

- **IClaudeService**: For AI-powered fix generation
- **GitHubClient**: For branch/commit/PR operations
- **NotificationSettings**: For configuration

### Data Flow

```
GitHub Webhook
    ↓
WebhookController
    ↓
PipelineOrchestrator (RCA + Analysis)
    ↓
[High Confidence?] → No → Skip Auto-Fix
    ↓ Yes
AutoFixService.GenerateFixAsync
    ↓
[Safe to Apply?] → No → Log Reason
    ↓ Yes
AutoFixService.ApplyFixAndCreatePRAsync
    ↓
GitHub PR Created
```

## Future Enhancements

Potential improvements for the auto-fix feature:

1. **Learning from feedback**: Track which PRs get merged vs. closed to improve fix generation
2. **Test generation**: Automatically create tests for fixes
3. **Multi-file coordination**: Better handle fixes requiring changes across multiple files
4. **Preview mode**: Generate fix and post as PR comment without creating branch
5. **Fix templates**: Pre-defined fix patterns for common issues
6. **Rollback detection**: Detect if fix causes new failures and auto-close PR
